The Problem

Designers forget the edges

Most design flows only cover the happy path. The states users encounter when something goes wrong — or when there's nothing there yet — are often left until the last minute or skipped entirely.

  • ❌ Empty states are designed as afterthoughts
  • ❌ Error messages are generic and unhelpful
  • ❌ Edge cases cause bugs that reach production
  • ❌ Documenting edge states takes hours of manual effort
The Solution

How It Works

Smart parsing pipeline

✍️
1. Natural Language Input
User types a flow like
"Sign up → verify email → land on dashboard"
🔎
2. Step Classification
Regex patterns detect step type (auth, commerce, upload, social, search…) from keywords
🧠
3. Context-Aware Generation
Each category has tailored state definitions — checkout errors ≠ upload errors
🎨
4. Preview Components
States are matched to one of 30+ UI preview variants (toast, modal, inline banner…)
🔊
5. Tone Application
Every string passes through a tone selector: professional / playful / chaotic
📋
6. Export
Copy any card as a PNG screenshot using html2canvas, ready to paste into Figma or Notion

Data Model

Clean TypeScript types

type Tone = "professional" | "playful" | "chaotic";
interface State {
  title:     string;                            // e.g. "Email already registered"
  microcopy: string;                            // descriptive body text
  cta?:      string;                            // call-to-action button label
  type:      'empty' | 'error' | 'edge';     // state category
  preview:   PreviewVariant;                    // which UI component to render
}
interface FlowStep {
  stepName:        string;    // e.g. "Sign up"
  stepDescription: string;    // e.g. "User creates a new account"
  states:          State[];   // always 4 per step
}

State definitions live in src/data/states.ts — pure data, no logic. Generation logic is isolated in src/utils/flowParser.ts.

Technical Highlights

What makes it tick

🧩
Declarative state data
states.ts holds pure data objects. Generation logic and data are completely separated, making it easy to add new state types or categories.
🔄
Real-time tone switching
Changing tone re-runs the parser with a new tone parameter — all ~20+ cards update simultaneously with zero page reload.
🏷️
Smart noun extraction
The parser reads context from the user's own words to personalise copy — "your items", "your posts", "your files" — not just generic placeholders.
🧪
30+ preview variants
States are mapped to real UI patterns: toast, modal, inline-banner, upload-zone, empty-inbox, locked-feature, and more — making previews feel authentic.
